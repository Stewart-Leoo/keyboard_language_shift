# Keyboard Language Switcher

> 双键盘输入语言锁定工具 —— 为每块物理键盘绑定独立的中/英文输入状态

---

## 项目简介

设计这个程序的想法已经很久了，这次终于付诸实践。我一直觉得各种情形下，中英文交替输入都是一件很烦人的事，一方面是系统输入法的切换，另一方面是输入法内按shift键之类切换中英文模式，另外capslock开启时通常会拦截中英切换指令，这几点叠加起来最终的输入体验就很糟糕。

所以我很早几年前就一直想在桌面上可以同时拥有两块键盘，一块输入中文~~（另一块也输入中文）~~，一块输入英文，我只需要双手在键盘之间转移，而不用受切换操作烦扰，像一个双刀流剑士，像青霞和紫霞。我相信大部分人听说后会觉得这很蠢，但是我也相信一定也会有人觉得，这真的很酷。

这个想法的核心逻辑就是一段宏代码，检测到键盘切换时，自动执行，变更到指定语言。写到这儿我突然想到，其实连接一个机械开关键锁定输入语言不得更改，应该会更可爱，就像iPhone15之前的拨动式静音键，非常实用。其实如果想要简洁直接绑定成一个快捷键执行切换宏然后禁用shift切换就足够了，可是这不就是shift键原本的功能吗，这个想法诞生的初衷就是因为键盘按键的不方便，笑了，这就是产品设计的日常困境吗哈哈哈。

总之这个项目就是实现了Windows系统在同时连接多块键盘的场景下（如一块 USB 有线键盘 + 一块 2.4G 无线键盘）， 配置每块键盘的默认输入语言，当检测到输入键盘切换时，自动执行语言修正，但是并未锁定，也就是只在切换时改到default语言，使用过程中依然可以依赖shift转换。

**Keyboard Language Switcher** 的具体操作顺序内容为：

1. **退格** —— 因为键盘的直接键入优先级太高了，也就是换键盘按下第一个键，还没等切换程序反应过来就输出了，想做到无缝切换几乎不可能，因为切换语言本身就至少需要一个按键操作，因此一定存在延迟。因此选择直接删除刚在错误语言状态下输入的字符，随后再重新键入，这反而比考虑延迟在精准时间插入切换宏的效果稳定得多。
2. **关闭大写锁定** —— 若 CapsLock 处于开启状态则自动关闭，排除大写锁定下无法切换语言的限制。
3. **切换输入语言** —— 键入配置好的快捷键，将输入法切换到目标语言，这里的快捷键是绑定到输入法上的单向语言切换热键，需要自行配置，我是用的是小狼毫，还没有了解过其他输入法能否实现。
4. **重新键入** —— 在正确的语言环境下重新输入刚才的字符

## 功能特性

- **实时键盘监测** —— 检测当前连接的 USB / 2.4G 外接物理键盘
- **输入语言锁定** —— 为每块键盘独立配置默认语言（EN / CN）
- **自动切换** —— 检测到键盘切换时自动执行语言修正序列
- **自定义快捷键** —— 通过 JSON 文件配置语言切换热键
- **持久化配置** —— 设置保存至 `keyboard_config.json`，重启后自动恢复
- **首次输入检测** —— 程序启动后首次输入也会触发语言修正
- **托盘常驻** —— 以系统托盘图标后台运行，不占用任务栏
- **按需设置** —— 右键托盘图标 → 设置，打开控制台命令界面

## 使用限制
- **切换键盘执行宏依然存在延迟**，所以切换键盘按下第一个键后慢一点点再按下第二个键，保证切换程序反应过来。不然第二个键很可能在第一个键删除、切换、重新键入后才被输出。
- **仅测试通过了 USB / 2.4G 接收器连接的外接物理键盘**，蓝牙键盘、虚拟键盘、内置键盘等没有尝试，不知道是否有效，另外作者也只实验了**win11系统**。
- **切键盘输入的第一个键最好是可退格的字符**，否则退格键依然会直接执行，删掉前一个字符，比如切键盘直接按退格，那么会再追加两个退格直接删掉三个字符。这一点之后如果有时间会考虑优化。

## 产品设想
语言切换功能的实现必然需要一次信号输入，无论是按shift或者热键、绑定物理按键开关、检测键盘切换信号，都是这个信号的不同表现形式，基于切换形式的不同，我想也就可以延伸出不同的适用功能和场景。
1. 按shift或者热键，这个是最简单最原始的实现方式，优点是一块键盘，缺点就是切换操作的频繁带来输入体验不佳。
2. 双键盘输入，将键盘切换信号识别为语言切换指令，也就是省去了手动按键切换检查的麻烦，多块键盘的模式会更满足追求输入体验的人群。
3. 物理切换键，设想一个开关、按钮或者扳键，用来锁定输入语言不得更改，类似iPhone15之前的拨动式全局静音键，物理按键的优势就是不易误触，天然适合用作锁定功能，侧重固定性而非灵活性。因此如果开发出消费使用的按键开关小产品，一定是用于锁定功能更合适，否则就没有和第1类方案竞争的必要了。

| 要求 | 说明 |
|------|------|

## 构建方法

1. 用 Visual Studio 打开 `keyboard_shift_dev/keyboard_shift_dev.slnx`
2. 将 `logo.png` 转换为 `logo.ico`（建议含 16×16 和 32×32 尺寸），放入 `keyboard_shift_dev/keyboard_shift_dev/` 目录
3. 在解决方案资源管理器中，将以下文件通过"添加 → 现有项"加入项目（若尚未加入）：
   - `InputConfig.h` / `InputConfig.cpp`
   - `InputSwitcher.h` / `InputSwitcher.cpp`
   - `TrayApp.h` / `TrayApp.cpp`
   - `resource.h` / `resource.rc`
4. 项目属性 → 链接器 → 系统 → 子系统：设置为 `Windows (/SUBSYSTEM:WINDOWS)`
5. 选择 `x64 Release` 配置，生成项目

## 使用方法

### 首次运行

1. 运行编译好的 `keyboard_shift_dev.exe`
2. 程序不会弹出窗口，在右下角任务栏托盘区可见程序图标
3. 程序自动在 exe 同目录生成 `keyboard_config.json` 配置文件

### 配置语言标签

1. 右键托盘图标 → **Settings...**，打开设置控制台
2. 输入 `l`，列出当前已连接的键盘
3. 输入对应编号，将该键盘的语言在 EN / CN 之间切换
4. 修改后自动保存到 `keyboard_config.json`

### 托盘右键菜单

| 菜单项 | 功能 |
|--------|------|
| ✓ Auto Language Switch | 点击切换自动语言修正的开/关状态 |
| Settings... | 打开控制台命令界面（双击图标同效）|
| Exit | 退出程序 |

### 控制台命令

打开 Settings 控制台后，可使用以下命令：

| 命令 | 功能 |
|------|------|
| `s` | 进入实时键盘状态显示（显示连接状态、活跃键盘、语言标签；按 `q` 退出）|
| `l` | 列出已连接键盘，输入编号切换语言标签（EN/CN）|
| `t` | 开启/关闭自动语言切换功能 |
| `q` | 关闭设置控制台（程序继续在托盘运行）|
| `h` | 显示帮助信息 |

## 配置文件

配置文件位于 exe 同目录，文件名 `keyboard_config.json`，首次运行自动生成。

```json
{
    "version": 1,
    "hotkeys": {
        "switch_to_english": {
            "ctrl": true,
            "shift": true,
            "alt": false,
            "key": "F11"
        },
        "switch_to_chinese": {
            "ctrl": true,
            "shift": true,
            "alt": false,
            "key": "F12"
        }
    },
    "keyboards": {
        "\\\\?\\HID#VID_XXXX&PID_XXXX&MI_00#...": {
            "friendly_name": "USB Keyboard",
            "lang": "EN"
        },
        "\\\\?\\HID#VID_XXXX&PID_XXXX&MI_00#...": {
            "friendly_name": "2.4G Keyboard",
            "lang": "CN"
        }
    }
}
```
